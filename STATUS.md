# Checkpoint 1 — Pick and proof of concept

As of October 29, 2026, our working choice is **Which sectors react most to unexpected FOMC policy news?** This develops the Fed idea in the original README because the event dates, ETF prices, and a published policy-news measure can be obtained with a manageable amount of code. The proof of concept uses the last five scheduled 2024 FOMC meetings (June 12, July 31, September 18, November 7, December 18), three sector ETFs (XLK, XLF, XLU), and SPY. This is a feasibility sample chosen by calendar order, not by observed returns. The USMPD monetary-event (ME) factor represents policy news across the statement and press conference; it is not the actual rate change minus a literal pre-meeting target expectation. Expected target changes remain missing.

The executable pipeline now produces **15 meeting–ETF observations**, **45 daily calculation-trace rows**, adjusted-price inputs, source URLs/retrieval timestamps/SHA-256 hashes, and a validation summary. All five events have ME observations and complete required price windows. Official statements were inspected to verify 14:00 Eastern releases and the coded hold/cut decisions. A separate Decimal-based check recomputes every event return and three-day cumulative market-adjusted return from exported prices. For September 18, XLK underperformed SPY by approximately **0.615944 percentage points**. The small difference from the old README's 0.615965 figure comes from a different price retrieval vintage; the new run preserves its exact inputs. Initial execution failed because the default Windows Python alias was unusable and sandbox DNS was blocked; the bundled Python runtime and an approved download run resolved those issues. No dashboard, full-sample model, or causal conclusion is claimed.

Questions for the instructor: Is the published USMPD ME factor acceptable for the revised policy-news question? Is a planned 2016–2025 sample with the broader ETF universe appropriate, and should emergency meetings be analyzed separately? Is a retrospective event study with meeting-level uncertainty sufficient, or is a predictive/LLM component required? Before November 9 we need to expand the data audit, decide the full-sample specification before inspecting results, build the dashboard skeleton, and write the checkpoint self-audit. The present five meetings cannot support reliable sector rankings or meaningful regression inference. Daily windows include other news; the November event overlaps the post-election period. The published factor vintage is retrospective, and subtracting SPY imposes a beta-one benchmark. These limitations must remain visible in later outputs.
